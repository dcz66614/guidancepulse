## 2. Cold-start design decision (v1.1.0 §9.6 / IMPLEMENTATION_PLAN §8.3)

v1.0.0 code excluded the seed spawn from the p95 sample ("NOT part of the p95 sample").
That conflicts with v1.1.0: "这 100 次必须包含冷启动样本；冷启动同时属于 `n=100`" /
"不得把冷启动从 100 样本剔除". Fix applied: the seed (first-ever spawn) is timed
sample #1. Ordering is seed → 5 warm-ups (untimed) → 99 further timed runs = 100 timed
samples. The seed must come first because no Write call can return ALLOW before a lease
exists, so the first spawn cannot be a warm-up; warm-up count was not increased (still 5).

Transparency note: sample #1 is the PostToolUse **Read** seed, while samples #2–100 are
PreToolUse **Write** calls. It is a fresh `node` subprocess with the same dominant costs
(spawn, Node startup, better-sqlite3 load, JSON parse, SQLite, match, decision, output,
exit); the parent task explicitly required the first spawn to fall inside the 100 timed
samples, and this is the only ordering that satisfies both "5 warm-ups excluded" and
"cold start inside n=100". `cold_start_sample_index: 0` marks it in `perf-hook.json` and
in the gate report, so any re-check can see exactly which sample it is. In both runs the
cold start was also the max (359.01ms standalone / 382.18ms gate run) and p95 still passed
with wide margin.
